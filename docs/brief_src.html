VEIL — Verifiable Entity Integrity Layer

Track 3 · Secret Wards · Hide the identity. Preserve the medicine. · Offline · CPU-only · Python standard library · engine 3b4e605 (known-good-8) · github.com/ThatKJ/VEIL

1. What VEIL is

VEIL is a clinical privacy release-assurance engine for fragmented, multilingual Indian hospital exports (CSV/TSV, super-header/EAV/stacked tables, nested/stringified/coded-column JSON, embedded structured blocks, FHIR R4, HL7 v2, notes across Latin, Devanagari, Bengali, Gurmukhi, Gujarati, and 8 Indic digit scripts). It first resolves each patient across files, scripts, and hospitals, then measures re-identification risk on the patient's pooled profile, and escalates generalisation only when rare. An independent verifier and truth-free Privacy Passport audit every release. Zero LLMs, zero ML models, zero network.

2. Architecture (two passes)

input/ ─► 1 Ingest: encoding/mojibake + CleverCSV delimiter sniffing, depth/budget guards, symlink/binary/malformed quarantine
       ─► 2 Structure: EN/HI/regional/South-Indic/Kannada lexicons; 2-row super-header/EAV CSV; stringified & coded JSON; HL7 v2; SQL INSERT
       ─► 3 Harvest: names, strong IDs, household/ration cards (non-linking), phones, compact/Indic/period DMY dates, relatives, places
       ─► 4 Identity graph: strong IDs + phones (up to 32 clusters), Indic skeleton + secondary-blocked FS; cluster-level given-name veto
       ─► 5 Pooled-profile privacy: release equivalence classes (k5/k10) + rare-ICD/age≥80 escalation; consistent ARX bands; HMAC date shifts
       ─► 6 Rewrite: clinical (/cumm etc.) & Dr./Sr./Sis./N/O/DEO protected first; URL/wa.me/tel:, base64/hex (unblinded), keys, filenames
       ─► 7 Verify: O(N) harvested-token sweep ─► sanitized/ (contained) + report.json + records.jsonl + offline Privacy Passport

3. Distinctive engineering & prior-art attribution

  • Pooled longitudinal privacy (adapted from ARX) — risk is assessed per resolved patient across records, bringing risk-driven equivalence-class anonymisation to pooled multilingual free text and structured schemas offline.
  • Zero-false-merge identity graph (adapted from Splink & Dedupe) — Fellegi–Sunter blocking + TF weighting with cluster-wide given-name conflict vetoes, one-edit national-ID typo tolerance, and safe household-phone/ration-card handling.
  • Format-general scrubbing & protection (UCSF Philter, Presidio, i2b2, CleverCSV, FHIR R4) — handles unquoted delimiters, coded schema maps, JSON-in-CSV, embedded JSON blocks, URL paths, and 8 Indic numeral systems while protecting doses, labs, doctors, and nurses.
  • Truth-free Release Assurance (tools/veil_passport.py, dev/demo) — pairs every physical file 1:1 with SHA-256 report entries and audits residue, clinical expression/interval preservation, and pseudonym placement without ground truth.

6. Security, Scaling & Honest Limitations

  • RAKSHA_SECRET never touches disk/logs; A/A determinism 1.0, A/B shifts distinct; strict is_relative_to(sanitized) export containment; symlink/binary/>64-deep JSON quarantined.
  • 31/31 unit tests pass (`unittest`, contracts, offline blocked-socket, 5 MB ReDoS, strict bounded `ast.literal_eval`, Passport 200/200). 100k x 100k unique patients in 13.95s / 707.5 MB (`0` quarantined).
  • Local harness scores omit sealed scaling weight and no finite test proves anonymity outside the published attacker model; Passport sampled clinical expressions kept does not equal ground-truth medical_kept.
  • Non-Devanagari name scripts abstain safely from cross-script merging to prevent false merges; H20 multi-row block probes (`lab_test/value`) remain unaligned by single-row CSV truth lookup. Local Docker inactive.
