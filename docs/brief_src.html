VEIL — Verifiable Entity Integrity Layer

Track 3 · Secret Wards · Hide the identity. Preserve the medicine. · Offline · CPU-only · Python standard library · engine 70f77c8 (known-good-7) · github.com/ThatKJ/VEIL

1. What VEIL is

VEIL is a clinical privacy release-assurance engine for fragmented, multilingual Indian hospital exports (CSV/TSV, nested JSON, JSON Lines, FHIR R4, HL7 v2, Markdown/INI notes across Latin, Devanagari, Bengali, Gurmukhi, and Gujarati scripts). It does not mask documents one at a time. It first resolves each patient's records across files, scripts and hospitals, then measures re-identification risk on the patient's pooled profile, and escalates generalisation only for patients who stand out. An independent verifier and truth-free Privacy Passport audit check every release before it ships. Zero LLMs, zero ML models, zero network.

2. Architecture (two passes)

input/ ─► 1 Ingest: encoding/mojibake + CleverCSV delimiter sniffing, depth/budget guards, symlink/binary/malformed quarantine
       ─► 2 Structure: EN/HI/regional/Kannada lexicons + value shape; recursive JSON/array-table/KV/HL7 v2 discovery; bounded literal JSONL
       ─► 3 Harvest: names, strong IDs, phones, DOB/ages, relatives, places; real-record rec_ids separated from metadata surrogates
       ─► 4 Identity graph: strong IDs + household phones (up to 32 clusters), Indic skeleton + secondary-blocked Fellegi–Sunter;
            whole-cluster cannot-link (one-edit ID typo tolerance); fixpoint passes; HMAC-SHA256 pseudonyms
       ─► 5 Pooled-profile privacy: release equivalence classes (k5/k10) + rare-ICD/age≥80 escalation; consistent ARX bands; HMAC date shifts
       ─► 6 Rewrite: clinical & Dr./Sr./nurse spans protected first; hidden channels (JSON keys, filenames, HL7, base64, hex, URLs)
       ─► 7 Verify: O(N) harvested-token sweep ─► sanitized/ (contained) + report.json + records.jsonl + offline Privacy Passport

3. Distinctive engineering & prior-art attribution

  • Pooled longitudinal privacy (adapted from ARX) — risk is assessed per resolved patient, not per record, bringing risk-driven equivalence-class anonymisation to pooled multilingual free text plus structured records offline.
  • Zero-false-merge identity graph (adapted from Splink & Dedupe) — Fellegi–Sunter blocking intersect + term-frequency weighting with whole-cluster cannot-link constraints and household-phone multi-cluster support.
  • Clinical-first scrubbing & dialect handling (UCSF Philter, Presidio, Nottingham i2b2, CleverCSV, Indic transliteration, FHIR R4) — protects doses, labs, ICD-10 codes, doctors, and nurses first before rewriting PII.
  • Truth-free Release Assurance (tools/veil_passport.py, dev/demo) — independently audits structural integrity, privacy residue (incl. base64), clinical expression/interval preservation, and pseudonym placement without ground truth.

6. Security, Scaling & Honest Limitations

  • RAKSHA_SECRET never touches disk/logs; A/A determinism 1.0, A/B shifts distinct; strict is_relative_to(sanitized) export containment; symlink escape & >64-deep JSON quarantined.
  • 28/28 tests pass (`unittest`, contract, offline blocked-socket, 5 MB ReDoS, Passport, strict `ast.literal_eval` bounds). 100k rows x 100k unique patients in 11.63s / 670.9 MB (`0` quarantined).
  • All local harness estimates exclude the sealed scaling sub-weight; no finite check proves anonymity outside the published attacker model.
  • Uninspected blind sets H20/H21 revealed unfamiliar scripts/formats where recall and canary coverage drop; left uninspected to preserve blind integrity. Local Docker daemon was inactive.
